## TAPT (tapt-api) — settled, verified 2026-08-25

`tapt-backend` deprecated — `tapt-api` is canonical (`tapt-api`, identity `tapt-api:1`).

- **Monorepo is NestJS workspaces, not Express singleton**: `apps/server` + `packages/db|api|env|config`, `type:module` ESM, `turbo` builds, `biome` lint (`biome.json:61L`). `tapt-backend`'s manual `Container.getInstance()` silo is retired — Nest DI is the only DI.
- **Contract-first over service-first**: ts-rest routers with `pathPrefix:"/api/v1"` in `packages/api/src/contracts/*.contract.ts` are source of truth; `apps/server/src/main.ts:20-24` explicitly has no `setGlobalPrefix`. DTOs from `z.infer`, mobile shares same contract — never re-type DTO per package.
- **Prisma single-predicate rule**: `common/prisma/errors.ts:25L` `isUniqueViolation/isNotFound` is only place that checks `code==="P2002|P2025"` with `instanceof`. Every repo's `create|update` wraps with it → `ConflictError`; use-cases never catch Prisma. Import via `@tapt-api/db/prisma` only.
- **Denormalize then transactionally refresh**: `License.current*` and `Delivery.totalPaidCents` cache latest totals to avoid scans; `renew|void|recordPayment` must `$transaction` the cache update — direct model edit without it is a bug (schema comments `L283`, `L390`).
- **Guarded `updateMany` for concurrency**: payments, scratch scans, license renewals all use `updateMany WHERE <guard>` and throw `BusinessRuleError` on `count===0` instead of `find→update` races (`delivery.repository.ts:222L`, `scratch-scan-event.repository.ts:198L`).
- **Money as cents + void not delete**: `Int` cents everywhere; financial history (`DeliveryPayment`, `TillEntry.reversesEntryId @unique`, `Expense`) uses `voidedAt/voidReason` and `onDelete: Restrict` not `Cascade` — history never hard-deleted.
- **Partial indexes live in migrations only**: `scratch_scan_events_pack_shift_active_key` is migration `20260806120000`, not `schema.prisma @@unique` (`AGENTS.md:76`). Add new conditional uniques the same way.
- **Session invalidation via `tokenVersion` + Redis + hash**: `User.tokenVersion` + `tokenver:${userId}` cache (3600s) + SHA-256 hashed `refresh_tokens.token` (`token.service.ts:12-14`). Adding a new permission scope requires increment + cache bust.
- **Observability layered**: Winston redact + Sentry `@Catch()` + `LoggingInterceptor` `requestId` + `TransformInterceptor` uniform shape + `HealthModule` (Prisma `SELECT 1` + queue client) + BullMQ `attempts:3` + GrowthBook. Don't add ad-hoc `console.log` or unstructured `logger.info`.
- **Guard order is load-bearing** `app.module.ts:108`: `JwtAuthGuard` must be first `APP_GUARD` before `UserThrottlerGuard`/`RolesGuard`/`ShopAccessGuard`. Moved `JwtAuthGuard` from `AuthModule` to `AppModule` first `2026-08-30` to fix `POST /shops`/`POST /forms` `403 No authenticated user found` despite valid `Bearer` (GET without `@Roles` succeeded, POST with `@Roles` failed). `UserThrottlerGuard:4` also needs `request.user` for `userId` vs `ip` throttling.
- **Form 12-field `discriminatedUnion` + `FormValidationError 422`**: `Form` `L493-509` `schema Json` + `FormSubmission` `L511-524` `answers Json` — 12 types `text..signature` (`file/image/signature` as `https://` URL), `formFieldsSchema` unique `Set(names)` → `BusinessRuleError` (no `@@unique` on `Json`, so `400` from contract `.refine` for HTTP, `422` for direct use-case), `validateAnswersAgainstSchema` pure `common/domain/form-answer-validation.ts:13` (no Prisma), `FormValidationError` distinct from `ValidationError` → `422` via `global-exception.filter.ts:60`, `FormSubmissionRepository` cast `Record<string,unknown> → InputJsonValue` in repository only (`AGENTS.md:80`).
